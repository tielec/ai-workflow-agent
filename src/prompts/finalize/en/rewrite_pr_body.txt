## Section Writing Guidelines

1. **Summary of Changes**: Summarize the purpose and main changes in 1-3 sentences. Focus on "what changes" rather than technical details.
2. **Background & Purpose**: Explain why this change is necessary based on the Issue context. Include business value or technical challenges.
3. **Key Changes**: List changes by file or module. Each item should clearly state "what" was changed and "how".
4. **Review Focus Points**: Highlight areas that reviewers should pay special attention to. Focus on security, performance, breaking changes, and edge case handling.
5. **Test Results Summary**: Summarize test execution results. If test information is not available, state "Test information is not available".
6. **Impact Scope**: Describe the scope of functions/modules affected by this change. If there is no impact on existing functionality, explicitly state so.
